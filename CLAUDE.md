## Architecture Overview

Angular 21 SPA for football betting analysis, focused on draw (empate) streak tracking across 100+ international leagues. All components use the **standalone pattern** — no NgModules anywhere.

### Route Structure

```
/ → redirects to /hot-list
/hot-list     — main table showing draw stats for all leagues simultaneously
/liga         — detailed view for a single league (tabs: results, upcoming, historical, analytics)
/dashboard    — global histogram overview
```

`LayoutComponent` wraps all three routes, providing the navbar and league-selector sidebar.

### Data Flow

**Static data** lives in `public/Ligas/[LeagueName].json` — one file per league. Two schemas coexist:

**`temporadas` schema** (used by ~58 leagues):
```json
{ "descripcion": "...", "fuente": "livescore|sofascore", "tournamentId": "...",
  "temporadas": [{ "nombre": "...", "año": "2024", "seasonId": "...",
    "jornadas": [{ "numero": 1,
      "partidos": [{ "id": "...", "fechaHora": "DD/MM/YYYY HH:mm",
        "local": "...", "visitante": "...", "estado": "Ended|NS|Postp.",
        "goles": [], "resultado": { "golesLocal": 1, "golesVisitante": 0 } }] }] }] }
```

**`torneos` schema** (Honduras, Guatemala — multi-tournament leagues with Apertura/Clausura):
```json
{ "descripcion": "...", "fuente": "Sofascore",
  "torneos": [{ "tipo": "Apertura|Clausura", "nombre": "...", "temporada": "24/25",
    "tournamentId": "...", "seasonId": "...",
    "jornadas": [{ "numero": 1,
      "partidos": [{ "id": "...", "fechaHora": "DD/MM/YYYY HH:mm",
        "local": "...", "visitante": "...", "estado": "Ended|NS|Postp.",
        "goles": [], "resultado": { "golesLocal": 1, "golesVisitante": 0 } }] }] }] }
```

`gen_historico.mjs` only reads `liga.temporadas` — it does **not** support the `torneos` schema. Running it on Honduras or Guatemala will silently produce empty output.

**Pre-computed streaks** are in `public/historico/[LeagueName].json`, generated by:
```bash
node scripts/gen_historico.mjs LeagueName   # LeagueName must match the file in public/Ligas/
node scripts/top_marcadores.mjs             # Analysis tool: finds leagues where top-N most frequent scores are all draws
```
Run `gen_historico.mjs` after updating a league's JSON. Output structure: `{ nombrePublico, temporadas: [{ temporada, conteos[] }] }` where `conteos` is the array of match-count gaps between draws each season.

**Live data** is fetched at runtime from external APIs via three proxied routes:
- `/v1/api/*` → `https://prod-public-api.livescore.com` (Livescore results)
- `/en/football/*` → `https://www.livescore.com/en/football/` (Livescore web content)
- `/api/sofascore/*` → `https://www.sofascore.com/api/v1` (Sofascore odds/stats)

All proxy routes spoof browser headers (User-Agent, Origin, Referer). In dev, `proxy.conf.js` handles all three. In production (Vercel), `vercel.json` handles the Livescore routes and `api/sofascore/[...path].js` is a serverless function for Sofascore.

### Data Sources per League

Each league in `LigasService` uses either Livescore or Sofascore as its live source:
- If `sofascoreId` is set → uses Sofascore API
- Otherwise → uses Livescore API via `archivoLigas` path

The `enable` flag (1/0) controls whether a league appears in the hot-list.

**Date formats** differ by source — three formats coexist in the codebase:
- Livescore: 14-digit string `YYYYMMDDHHMMSS` (field `Esd`) — use `esdToTimestamp()`
- Sofascore: Unix timestamp in seconds (field `startTimestamp`) — use `timestampToDateStr()`
- Static JSON / display: `DD/MM/YYYY HH:mm`

### Service Layer (core/services/)

| Service | Role |
|---|---|
| `LigasService` | Registry of all ~140 league configs. Key methods: `tieneHistorico()`, `tieneAmbosArchivos()` (used to show ✓ in email). |
| `HotListService` | Fetches all leagues in parallel (`mergeMap(3)` for league requests, `mergeMap(4)` for Sofascore rounds — rate limiting against external APIs), computes draw streaks (`conteo`), percentages, and max records. Most complex service. |
| `LigaDataService` | Fetches and processes data for one selected league. Supports both API sources. Exposes `apiError` signal; when set, `liga-page.component.ts` activates `modoFallbackHistorico` and shows only cached data. |
| `EmailHotListService` | Builds HTML report with 4 sections (Principales, Máximo Conteo, HOT, Histórico Acumulado) and sends via EmailJS. |
| `PdfHotListService` | Exports current view as PDF via html2pdf.js. Filename: `reporte_YYYY-MM-DD_HHmmss.pdf`. |
| `SchedulerHotListService` | Fires at 6:00, 11:00, 16:00, 21:00 UTC daily using RxJS `timer()`+`merge()`. Toggle via signal. |
| `ThemeService` | Light/dark toggle; persists to localStorage, respects `prefers-color-scheme`. Applied via `data-theme` on document root. |

Components inject services with `inject()` (not constructor injection).

### State Management

Angular **signals** are used for reactive state — `signal()`, `computed()`, `effect()`. RxJS is used only for HTTP calls and scheduling. No RxJS subjects or NgRx.

### Key Interfaces

Defined in `src/app/core/interfaces/results.interface.ts`: `Liga`, `Event`, `HotCheck`, and Sofascore-specific shapes (`SofascoreEvent`, `SofascoreEventsResponse`, etc.). Check these before adding new properties.

`LigaHomologada` is defined at the top of `src/app/core/services/ligas.service.ts` (not in the interfaces file).

`EpsStatus` enum: `'FT'` (Finished), `'NS'` (Not Started), `'Postp.'` (Postponed).

### Navigation Gotcha

`/liga` relies on `LigasService.ligaSeleccionada` signal being set before navigation. Direct URL access to `/liga` (e.g. pasting URL or page refresh) renders an empty view — there is no route param; league identity is signal-only state.

### Adding a New League

1. Add `public/Ligas/[LeagueName].json` with match data
2. Register in `LigasService`: `{ archivoLigas, sofascoreId, enable, historico, ... }`
3. Run `node scripts/gen_historico.mjs LeagueName`
4. Add the league name to the `historicosDisponibles` Set in `LigasService` — without this, `tieneHistorico()` returns false and the league never appears in the Histórico Acumulado or Top 10 of the email/PDF, even if the file exists.

### Sofascore Round Error Handling

`HotListService` processes all leagues in parallel and must swallow per-round errors silently. Each round request uses:
```typescript
.pipe(
  retry({ count: 1, delay: 800 }),
  catchError(() => of({ events: [] } as SofascoreEventsResponse))
)
```
Without the `catchError`, a 404 on the next scheduled round (which may not exist yet) kills the entire league — it disappears from the hot-list and all email/PDF sections. `LigaDataService` has the same pattern for its own round requests. Keep them in sync.

`HotListService.generarLista()` processes **all** leagues (no `enable` filter) — the `enable` flag is only used by UI components to decide what to display.

### Styling

SCSS + Bootstrap 5.3.8. Bootstrap CSS is imported globally via `angular.json` (not per-component). Global styles in `src/styles.scss`. Component-scoped SCSS per component. Angular Material is available but used minimally.

### TypeScript

Strict mode is fully enabled (`strict`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`, `noFallthroughCasesInSwitch`). Target ES2022. The `api/` directory is excluded from the Angular build (it's a Vercel serverless function, not part of the Angular app).

### Tests

Vitest 4 (not Jasmine/Karma). Only one spec file exists (`src/app/app.spec.ts` — a basic bootstrap smoke test). Test coverage is minimal.

### Deployment

Vercel reads `vercel.json` for rewrites. EmailJS keys (`serviceId`, `templateId`, `publicKey`, `destinatario`) must be set both in Vercel project settings and in `src/environments/environment.ts`.
